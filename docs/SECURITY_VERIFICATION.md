# Security verification (25 October 2026)

Each claim below was checked against the code and by a test that fails if the claim stops being true.
"Checked" means the test passes on every push (GitHub Actions) and was also run with a deliberate break to prove it can fail.

| # | Claim | How it is checked | Result |
|---|-------|-------------------|--------|
| 1 | Nobody can reach another customer's reports by changing an id | `test_cross_customer.py` calls every id-taking route as another customer (reports in all formats, PDF and its download link, share links, clients, members, invitations, sessions, webhooks and their deliveries). `test_route_coverage.py` fails when a new route with an id is not in that list. | Holds. 0 leaks. One earlier attack used a wrong path and proved nothing; fixed. |
| 2 | Agency members only reach what their role permits | `test_agency_roles.py`: every agency endpoint x 5 roles, compared with the permission matrix; non-members; removed members; free plan. | Holds. Limit: roles apply to the whole workspace; there are no per-client permissions yet. |
| 3 | API tokens have the same permissions and plan limits as sessions | `test_token_scope.py`: a token gets the anonymous answer on every route outside `/ci`; it stops when its owner is demoted. `test_integrations.py`: plan loss, revocation, throttling, allowance. | Holds. |
| 4 | Scheduled jobs respect verification and authorisation | `test_schedule_authorisation.py`: lapsed proof, address changed to another site, name re-pointed to a private address, site deleted, allowance used up, plan lost. | Holds. Schedules belong to the workspace, not to the person who made them. |
| 5 | Webhook destinations cannot reach internal services | `test_webhooks.py`, `test_ssrf_matrix.py`: 18 address tricks refused with nothing stored; address re-checked and pinned at every delivery; redirects not followed; Slack address pinned to one host and path shape (now also rejects a trailing newline). | Holds. |
| 6 | Verification and redirect handling resist SSRF and DNS rebinding | `test_fetcher.py`, `test_target.py`, `test_ssrf_matrix.py`, `test_targets.py`: validate, then connect to the checked address; every redirect hop re-validated; off-origin, downgrade and private redirects refused; the ownership file check uses the same fetcher. | Holds. All outbound requests on user input go through one path. |
| 7 | Account deletion handles workspaces, tokens, reports and jobs | `test_deletion_sweep.py`: fills every kind of record, deletes the account, then checks every table for rows pointing at the person or workspace and every text column for their email, name and webhook address. A schema test requires every reference to be CASCADE or SET NULL. | Holds. Open: a live paid subscription is not yet cancelled with the account (needed before Paddle goes live). |
| 8 | Subscription changes cannot grant or revoke entitlements wrongly | `test_subscription_invariants.py`: more than 7,000 combinations, 9 invariants. Only one function decides the plan, and no route writes subscriptions. | Holds. Decision for later: a paid plan that is lower than a plan the operator assigned by hand replaces it while the subscription lasts. |
