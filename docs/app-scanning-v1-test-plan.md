# App Scanning v1: test plan

Date: 26 Oct 2026. **No App Scanning test has been written or run.** This is the plan each batch must satisfy; results are added to `app-scanning-test-evidence.md` with the command and the actual output. Tests use mocked API responses and local fixtures; no untrusted code is run, no third-party system is scanned, and no live OSV call is made in CI.

| Area                          | Test                                                                                                                                                                                                                           | Phase                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- |
| Dependency parsing            | Valid npm lockfile v2 and v3, `package.json`, pinned `requirements.txt`; duplicates; scoped names; unpinned ranges reported as unsupported, not guessed                                                                        | C                                 |
| Malformed and oversized input | Invalid JSON, wrong types, depth above the cap, over 2 MB, over 20 000 packages, binary, archive magic bytes; each ends in a clean 4xx, nothing stored                                                                         | C                                 |
| Lookup normalisation          | Mocked responses with and without severity, ranges, fixed versions, aliases, withdrawn records, pagination                                                                                                                     | D                                 |
| Lookup failures               | Timeout, 5xx, 429, oversized response, malformed body, partial batch: scan is **Incomplete** and names what failed, never clean                                                                                                | D                                 |
| Outbound request              | Host is the constant; only ecosystem, name, version are sent; user-supplied URLs are never fetched; redirects not followed                                                                                                     | D                                 |
| Redaction                     | Canary secret injected into manifest names, evidence, titles, paths, CI payloads: absent from database rows, API bodies and errors, PDF text, webhooks, alert emails, captured logs                                            | B, E                              |
| CI submission                 | Strict schema; unknown fields rejected; length and count limits; enum severities; XSS and Markdown injection in titles render as text in page and PDF; secret-like content rejected with a fixed message that does not echo it | E, F                              |
| Authentication                | No token, bad token, revoked token, token for another workspace: 401 or 403, no data                                                                                                                                           | H                                 |
| Authorisation                 | Role matrix per route (viewer cannot create or triage); reuse existing permissions                                                                                                                                             | C, H                              |
| Cross-customer                | Projects, scans, findings, reports, uploads of another workspace return 404; added to the route-coverage test                                                                                                                  | C                                 |
| Plan limits                   | At limit, over limit, concurrent starts, failed run not counted, web usage unaffected, Free per decision D2, downgrade preview                                                                                                 | H                                 |
| Timeouts and states           | Parser time limit, tool timeout in the submission, each of the five states rendered distinctly                                                                                                                                 | C, G                              |
| Report consistency            | Counts in page, API, PDF and JSON agree; scanner and database metadata present; limits block present; web report golden file unchanged                                                                                         | G                                 |
| Action token handling         | Token masked, not in process list, not in logs (canary); exit codes 0, 1, 2; retries do not duplicate runs (idempotency)                                                                                                       | H                                 |
| No execution                  | Patched `subprocess` and read-only directory during parsing; fixture with lifecycle scripts; assert nothing runs or is written                                                                                                 | C                                 |
| No score                      | API, UI and PDF for App Scanning contain no `score` or `grade` field or text                                                                                                                                                   | C, G                              |
| Web regression                | Entire existing backend and e2e suites unchanged and green; axe in both themes for new pages                                                                                                                                   | every batch                       |
| Migration                     | Up and down on a scratch database; no web table altered                                                                                                                                                                        | C                                 |
| Load                          | autocannon at the real instance CPU limit for upload and submission routes; results recorded, not assumed                                                                                                                      | before any allowance is published |

Each batch also runs: ruff, mypy, the full backend tests, frontend typecheck, lint, unit tests and build, the secret scan, `pip-audit` and `npm audit` for any new dependency, and a diff review before the patch is offered.
