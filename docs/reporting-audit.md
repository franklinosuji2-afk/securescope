# Reporting audit

Phase 4 of the product-quality brief. Labels: **Verified** (tests), **Risk**, **Recommendation**, **Not tested**.

## What was checked

One scan with four findings (open, accepted risk, false positive, resolved) and one check that could not run, rendered as Markdown, HTML, JSON, CSV and PDF. New file: `test_report_consistency.py`.

## Verified: the formats agree on

- **Findings:** every format lists every finding, whatever its status, except as noted below.
- **Score:** the score appears in Markdown, HTML, JSON and the PDF. CSV is a per-finding table and has no score column by design.
- **What was not checked:** Markdown, HTML and PDF each state the checks that could not run and why. A skipped check is never reported as passed.
- **Limits:** Markdown, HTML and PDF each say the report is not a penetration test and that an empty or high result is not proof of security.
- **Resolved findings:** shown as "No longer detected" with the statement that this does not prove a fix; never as "fixed".
- **Escaping:** report values are escaped for each format (existing tests in `test_db_and_reports.py` and `test_pdf_report.py`: hostile evidence stays inert, the PDF renderer cannot load anything from the network or disk).

## Defect found and fixed

- The client PDF leaves out findings marked as false positives (they are not counted in the totals or the risk rating), but it did not say so, while Markdown and HTML list them with the label "Marked false positive". A reader comparing two exports could not tell why they differed. The PDF now says "N finding(s) marked as a false positive by the team is/are not listed in this report." Tests cover the note and that it does not appear when nothing was excluded.

## Risks and recommendations

| # | Finding | Type |
|---|---|---|
| 1 | The PDF is built from HTML and is checked here by extracted text, not by looking at the pages. Layout (the premium cover, page breaks, long evidence) is a separate, queued piece of work. | Not tested (visual) |
| 2 | Markdown and HTML list false positives; the PDF does not. This is deliberate for a client-facing document but should be known by anyone attaching both. | Documented |
| 3 | The CSV has no scan-level data (score, date, coverage). Fine for finding tables, wrong if used as the only record of a scan. Consider a header comment line or a note in the docs. | Recommendation |
| 4 | Report IDs and "generated by" lines differ per format by design; nothing compares them. | Informational |
